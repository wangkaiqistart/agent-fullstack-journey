## 学习方式

每次学习完成一个闭环：

1. **明确问题**：本节要解决什么，自己目前哪里不懂。
2. **学习资料**：阅读或观看一个主题，记录来源位置。
3. **独立尝试**：先写最小练习，再让 AI 解释、排错或检查。
4. **改变条件**：修改一个参数、输入或异常条件，观察结果。
5. **记录理解**：用自己的话解释原因，留下未解决问题。
6. **提交成果**：提交本次笔记与练习，记录实际验证情况。

判断掌握程度时，区分“看过”和“会做”：能解释、能独立运行、能修改条件并说明结果，才算完成本主题的实践。

### 笔记骨架

```markdown
# 本节主题

## 解决什么问题
## 核心概念：用自己的话解释
## 最小示例与运行方法
## 实验结果：输入、输出、异常情况
## 踩坑与原因
## 尚未理解的问题
## 课程来源：文件名、页码或视频时间点
```

重点记录理解变化和实验结果，不以抄全课件为目标。课程观点、自己的推断和实际验证结果应明确区分。

### Demo 要求

每个 Demo 的 README 至少说明：

- 学习目标与对应课程来源。
- 环境要求、依赖安装和运行命令。
- 所需环境变量名称，以及不含真实凭据的配置示例。
- 示例输入、预期结果与实际验证结果。
- 已知限制，以及一个可以继续尝试的变化。

依赖环境可以按章节共用；存在版本冲突或技术栈不同时再独立管理。记录实际使用的依赖版本，避免隔一段时间后无法复现。

## 技术栈与阶段项目

先跟随各节课程使用的技术栈。当前已读取的阶段讲义涉及 Python、FastAPI、Pydantic，以及 Node.js / TypeScript；具体版本随练习的依赖声明确定。

掌握完整能力后，可选做 Java / Spring AI 对照实现，并记录设计差异，无需每节课同时维护两套代码。

当前已知的阶段练习方向为：

1. **统一模型调用服务**：从最小调用逐步加入流式输出、结构化输出、模型路由及调用记录。
2. **Agent 工具调用基础设施**：逐步理解工具定义、参数校验、执行、超时、权限边界与 MCP 接入。

以上是学习方向，尚未实现。更完整的验收范围应在学习对应阶段时依据课程讲义确定，后续项目随课程更新补充。

## 第一次学习

建议预留 60～90 分钟，完成以下内容：

- [ ] 创建进度表与第一篇模型 API 笔记。
- [ ] 在引入环境文件前配置 `.gitignore`，忽略密钥、虚拟环境和本地产物。
- [ ] 编写通过环境变量配置的最小模型调用 Demo。
- [ ] 观察一次成功调用和一次失败调用，记录耗时、结果及原因。
- [ ] 区分真实接口验证与 Mock 验证；没有调用条件时明确记录未执行。
- [ ] 自己解释调用过程，提交笔记与练习。

第一次的目标是一篇自己的笔记、一个可重复运行的 Demo，以及一次清楚的提交。
